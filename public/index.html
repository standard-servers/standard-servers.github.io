Standard Servers

One middleware, every framework

Write server utilities and middleware once, then run them on any Fetch-based framework.

standard-context standard-middleware

The problem

Modern JavaScript server frameworks all speak the Fetch API: a Request comes in, a Response goes out. But each one wraps it in its own context or event, so a utility written for one framework doesn't work in the others.

Same logger, written three times. Now multiply that by every library and every framework.

The idea

Inspired by Standard Schema, frameworks keep their own context and add one property to it: ~standard.

Libraries read the request and shape the response through it, without caring which framework they're running in. Frameworks can adopt it without breaking anything.

Proposal 1

StandardContext

A standard way to read the incoming Request and prepare the outgoing Response. Frameworks can also expose runtime-specific data and waitUntil.

Proposal 2

StandardMiddleware

Built on top of StandardContext, a middleware is an async function of (context, next). Frameworks compose a stack of them like koa-compose: code before await next() runs on the way in, code after it runs on the way out.
